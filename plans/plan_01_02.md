# Plan 01-02: Backend Auth System

## Objective
Upgrade auth to support roles (admin, manager, cashier, warehouse, analyst), dual-token (access + refresh), profile endpoints, and role-based authorization.

## Files to Modify

### 1. `Backend/models/userModel.js` — Extend schema
Add fields:
- `role`: String enum `["admin", "manager", "cashier", "warehouse", "analyst"]`, default `"cashier"`
- `store`: ObjectId ref `"Store"`
- `isActive`: Boolean, default `true`
- `refreshToken`: String

**Migration**: Since early-stage dev, drop collection or add fields manually.

### 2. `Backend/services/authService.js` — NEW file
Functions:
- `generateAccessToken(userId)` — sign JWT with `config.jwt.secret`, expiry `15m`
- `generateRefreshToken(userId)` — sign JWT with `config.jwt.secret`, expiry `7d`
- `verifyAccessToken(token)` — verify and return decoded payload
- `verifyRefreshToken(token)` — verify and return decoded payload
- `setRefreshCookie(res, token)` — httpOnly cookie named `"refreshJwt"`, path `/api/users/refresh`, maxAge 7 days, sameSite `Strict`
- `clearRefreshCookie(res)` — clear the `refreshJwt` cookie
- `hashPassword(password)` — bcryptjs hash with salt 10
- `comparePassword(password, hashed)` — bcryptjs compare

### 3. `Backend/utils/generateToken.js` — Replace or re-export
- Either delete this file or make it re-export from `authService.js`
- Old single-token logic is replaced by dual-token system

### 4. `Backend/middleware/authMiddleware.js` — Add role authorization
- Keep existing `protect` middleware as-is (decodes JWT from `Authorization: Bearer <token>`, attaches `req.user`)
- Add new export `authorize(...roles)`:
  - Returns middleware that checks `req.user.role` against allowed roles
  - If not authorized, respond `403` with `{ message: "Role ${role} not authorized" }`

### 5. `Backend/controllers/userController.js` — Add/update handlers

| Function | Action |
|----------|--------|
| `registerUser` | Accept `store` field, create user, generate both tokens, return user + accessToken, set refresh cookie |
| `loginUser` | Find user by email, compare password, store refreshToken in DB (hash it), return both tokens |
| `logoutUser` | Clear refresh cookie, remove refreshToken from DB |
| `refreshToken` | Read refresh cookie, verify, find user by token, issue new access token |
| `getUserProfile` | Return `req.user` populated with store (using `.populate('store')`) |
| `updateUserProfile` | Allow name, email, password update |
| `getUsers` | Admin-only: list all users |

All use `express-async-handler` wrapper. Errors follow the convention:
```json
{ "message": "error description" }
```

### 6. `Backend/routes/userRoutes.js` — Add new endpoints
```
POST /api/users/refresh        → refreshToken
GET  /api/users/profile        → protect, getUserProfile
PUT  /api/users/profile        → protect, updateUserProfile
GET  /api/users                → protect, authorize("admin"), getUsers
```

Keep existing routes (`register`, `login`, `logout`) unchanged or enhance them.

## Acceptance Criteria
- [ ] User can register with name, email, password, store name → receives tokens + cookie
- [ ] Login returns access token in body + refresh cookie
- [ ] Token refresh works: POST /api/users/refresh returns new accessToken
- [ ] Logout clears cookie and DB token
- [ ] `authorize()` middleware blocks wrong roles with 403
- [ ] `/profile` returns user with populated store
- [ ] Existing todo routes still work (regression check)
