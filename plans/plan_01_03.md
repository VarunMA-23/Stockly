# Plan 01-03: Backend Store CRUD

## Objective
Create Store model, controller, and routes for multi-store support.

## Files to Create

### 1. `Backend/models/storeModel.js`
```js
Schema fields:
- name: String, required
- address: String
- phone: String
- gstin: String
- isActive: Boolean, default true
- timestamps: true
```

### 2. `Backend/controllers/storeController.js`
Functions (all using `express-async-handler`):
- `getStores` — Find all stores, support `?isActive` filter
- `createStore` — Validate required fields, create, return 201
- `getStoreById` — Find by ID, 404 if not found
- `updateStore` — Find by ID, update fields, return updated doc
- `deleteStore` — Delete from DB or set `isActive = false`

### 3. `Backend/routes/storeRoutes.js`
```
GET    /api/stores     → protect, authorize("admin"), getStores
POST   /api/stores     → protect, authorize("admin"), createStore
GET    /api/stores/:id → protect, getStoreById
PUT    /api/stores/:id → protect, authorize("admin"), updateStore
DELETE /api/stores/:id → protect, authorize("admin"), deleteStore
```

The `getStoreById` is accessible by any authenticated role (useful for profile display).

## Acceptance Criteria
- [ ] Store CRUD endpoints work (admin only for create/update/delete)
- [ ] All authenticated roles can view a store by ID
- [ ] Store data can be referenced by User model (for D1)
- [ ] GET /api/stores/:id returns populated store data
